# MyBot Learning Alpha-Beta

`MyBot` is a hybrid search bot for Infinite Hex Tic-Tac-Toe. It keeps the reliable part of the original plan, alpha-beta pruning, and replaces the hand-written leaf heuristic with a small learned value function.

## How It Works

1. The bot generates legal candidate placements near the active frontier of the board.
2. It also projects candidate moves along the three winning axes so urgent endpoints and one-cell gaps are not pruned away.
3. Candidate placements are combined into full two-stone turns.
4. Alpha-beta search evaluates those turns.
5. When search reaches the depth limit, it calls `LearnedValueFunction.evaluate(...)`.
6. The value function is trained from positions labeled by a deeper teacher search.

The evaluator blends the saved learned weights with a tactical guard rail. This keeps the bot from ignoring obvious wins or blocks when the learned weights are noisy.

The model is intentionally simple: a linear evaluator over board features such as longest line, open threes, open fours, open fives, closed fives, and center influence. Its output is squashed to `[-1, 1]`, where:

- `1` means a likely win for the bot.
- `0` means roughly balanced.
- `-1` means a likely loss for the bot.

## Is It Optimal?

This is an approximate learned heuristic, not a proof of perfect play. It becomes truly optimal only if the game is solved, or if every reachable state is labeled with exact minimax values. For this project, the practical goal is:

> alpha-beta handles tactical search, while the learned value function approximates the minimax value of non-terminal leaf states.

That gives the bot a real learning component without turning the project into a full reinforcement-learning system.

## Training

The live engine loads its starting weights from `src/learnedWeights.json`. It also performs a small amount of lazy in-memory training from the current position before searching. That live training helps the current browser session, but browser workers cannot write back to the project files.

For longer experiments, run:

```sh
corepack pnpm --filter @ih3t/bot-engine-mybot train:heuristic
```

The script generates legal self-play positions, labels them with the alpha-beta teacher, trains the value function, and saves the result to `src/learnedWeights.json`. The next time the frontend loads `MyBot`, it uses those saved weights automatically.

To run a longer training session:

```sh
MYBOT_TRAINING_MINUTES=60 corepack pnpm --filter @ih3t/bot-engine-mybot train:heuristic
```

To train from positions generated by games against the included Seal bot:

```sh
MYBOT_TRAINING_OPPONENT=seal MYBOT_TRAINING_MINUTES=60 corepack pnpm --filter @ih3t/bot-engine-mybot train:heuristic
```

In short:

- Sandbox play: learns a little in memory, useful only for that bot instance.
- `train:heuristic`: trains offline and persists the learned weights.
- `src/learnedWeights.json`: the saved training artifact the bot actually starts from.

## Playing Stronger Matches

The sandbox default timeout is low, so MyBot usually searches only two turns deep. For stronger games against Seal, raise the sandbox bot timeout to at least `3000ms`; `12000ms` lets it use an even deeper search. The candidate generator still prioritizes immediate wins and blocks at any timeout.

## Important Files

- `src/index.ts`: bot engine, alpha-beta search, learned evaluator, feature extraction, and lazy training.
- `src/mdpBellmanBot.ts`: separate MDP/Bellman bot. It uses adversarial Bellman backups for finite-horizon search and falls back to the saved approximate value function when exact solving is too large.
- `src/trainHeuristic.ts`: offline training helper for improving the starting weights.
- `src/learnedWeights.json`: persisted weights generated by the trainer.
- `index.ts`: compatibility re-export for older local imports.

## MDP Bellman Bot

`MDP Bellman Bot` is a separate sandbox option from `MyBot Learning Alpha-Beta`.

It models the game as:

- `state`: current board state.
- `action`: a legal full turn, usually two placements.
- `transition`: deterministic application of that turn.
- `value`: `+1` for a win, `-1` for a loss, approximate learned value otherwise.

For reachable finite horizons it applies the adversarial Bellman equation:

```text
V(s) = max_a V(T(s, a))   when MyBot moves
V(s) = min_a V(T(s, a))   when the opponent moves
```

Because the board is infinite, exact solving quickly becomes too large. At that point it uses `src/learnedWeights.json` as an Approximate RL value-function backup.
